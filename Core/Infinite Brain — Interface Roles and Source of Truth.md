# Infinite Brain — Interface Roles and Source of Truth

> **Lock sentence:** NotebookLM orients. Obsidian thinks. Supabase remembers. Ω-Audit governs. S4 returns the best admissible structure.

```yaml
project:

  synthesis_layer: S2 — Obsidian / Karpathy-style compiled wiki

  boundary_layer: S4 — BST informational nests
```

## The Three Tools and Their Roles

### NotebookLM — Orientation Interface

NotebookLM is the **reading and navigation surface** only.

Use it for:
- Explaining the project architecture
- Summarizing and comparing documents
- Detecting contradictions and missing links
- Generating navigational views and orientations
- Producing Obsidian-ready notes and summaries
- Producing Supabase-ready schemas and structures

Do NOT use it for:
- Canonical memory
- Final project repository
- Authoring doctrine
- Replacing Obsidian notes or Supabase records

NotebookLM autogenerated summaries are **not canonical** by default.

### Obsidian — The Idea Universe

Obsidian is the **primary living knowledge graph**.

This is where concepts, plates, essays, theorems, project maps, and evolving thought structures are authored and maintained.

Obsidian is canonical for:
- Wikilinked concept notes
- DR-GU law notes and lock chains
- Project architecture maps
- Theorem plates and contradiction records
- Evolving ideas not yet ready for Supabase

### Supabase — The Memory Substrate

Supabase SQL is the **durable Open Brain memory substrate**.

It stores:
- Structured sources, claims, claim-source links
- Embeddings (pgvector)
- Project objects and audit trails
- Omega audit results
- Retrieval-ready knowledge units
- State transition events (append-only)

Supabase is S1 carrier memory — the Open Brain.

## The Layer Chain

```text
S0  Domain generation — what is lawful to generate next
S1  Open Brain / Supabase — durable shared memory substrate
S2  Obsidian / wiki synthesis — compiled understanding
S3  Ω-Audit Ledger — admissibility and contradiction governance
S4  BST / informational nests — boundary-return intelligence
```

The system is a **recursive memory-governance machine**:

```text
S0 → T1 → S1 → S2 → T2 → S3 → S4 → T3 → S0
```

- T1 generates admissible domains
- T2 selects realized branches
- T3 returns witness-memory to constrain the next S0

## The Consortium Architecture

Multiple AI clients and human collaborators share one durable memory layer (S1), while synthesis and canonization remain governed (S3).

```text
Clients: ChatGPT, Claude, Cursor, Claude Code, future agents
         ↓
S1 Open Brain (Supabase) — shared persistence layer
         ↓
S2 Synthesis (Obsidian wiki, theorem plates, project maps)
         ↓
S3 Ω-Audit (contradiction ledger, admissibility decisions)
         ↓
S4 BST nests (boundary search, return-path indexing)
```

## Default Operating Rule

When using any tool in this consortium:

1. Explain architecture clearly
2. Map ideas back to their source documents
3. Identify contradictions, missing links, unresolved claims
4. Produce Obsidian-ready notes, maps, and summaries
5. Produce Supabase-ready schemas, tables, retrieval structures
6. Preserve the distinction between orientation, authorship, memory, and governance

**Canonical knowledge** must be reflected in Obsidian and/or Supabase Open Brain, with Ω-Audit applied when claims become reusable doctrine.
